# langChain 和 langGraph 的差别

初学Agent的朋友经常搞不明白 langChain 和 langGraph，觉得都是搭建智能体的技术栈，如果粗查文章或者询问智能体的话，给出的答案也都零零散散，有的说 langChain 偏基础工具，有的说 langGraph 能做流程编排，新手小白很容易被搞得一头雾水。

其实要讲清楚他俩的区别要从大模型的发展历史讲起。

## 早先的Agent

早期的Agent是以语言大模型和人沟通交谈的方式面世的，回想起2022年爆火的ChatGPT，如果您使用过它的话会被他犀利的逻辑对答所震撼，一些常识问题，或者计算推理型问题他能解答的游刃有余，但是如果这个时候问他一些最新的知识或者热点，他却答不上来，为什么，因为他没学过。

这个阶段大模型已经具备思考能力了，但是只是一个小孩子，有个好用的脑子，并且学习了一堆常识科普知识，与人正常沟通没什么问题。

紧接着工程师在 Agent 中给他加上了知识搜索的能力，这个时候 Agent 可以给我们爬最新的知识，辅助我们工作或者学习了。

到这个阶段，Agent的大部分功能还停留在搜索，解答上。同时第一批Agent也都呼之欲出了，有专门辅助炒股的，专门进行健康咨询的，帮忙解数学题的.....

这个时候专门进行Agent开发的框架 LangChain 就出现了，它的工作就是让 Agent 知道自己是谁，能干什么，从而专注于某一领域的服务。

**提问题 —> 知识索引 —> 片段召回 —> 大模型组织语言进行问题解答**

成了 Agent 的一套标准范式，整体就是一条线跑下来，LangChain也就这么被设计出来了，它可以通过业内标准协议来绑定大模型，可以让流程去RAG进行检索，可以完成文档的切片，融合到一起让大模型回答。

但是这种方式缺陷也是很明显的，流式的工作模式让Agent不会拒绝问题，不会反思，不会琢磨自己给出的答案对不对，就算你问他一个莫名其妙的问题，他也会用已有的知识给你奇思妙想的回复，所以大家觉得这种 Agent 很二，这就是咱们老说的飘逸，幻觉。

## 更先进的 Agent

早期Agent暴露的缺陷，让人们不得不重新设计Agent应该怎么思考，是应该像一个不负责任的外包，凑合把活儿干完。还是应该有自己的思索，反复确认后交付高质量的内容。

于是人们开始摒弃链式组合这种一口气干完活的思路，反而给Agent放权，让模型自己去思考做哪些，做的对不对，能不能交付给别人，于是这个阶段 ReAct，Agentic 这些设计模式诞生了，随之新的框架 LangGraph 也就被设计出来了。

如果要让模型自己去思考下一步怎么办，就不能把代码写死成 步骤一、步骤二、步骤三...，于是引入了一个概念叫**节点**，我把要做的工作都分为不同的节点，并在一开始设定好一个节点相互调用的顺序，但是这些节点在每个环节都可以切入模型自己的思考和判断，如果模型认为这个阶段有歧义则自行去调用分歧节点。

打个比方，我问模型“今年的股市为什么一蹶不振”，模型会“分析问题—> 知识检索 —> 总结答案 —> 审视答案 —> 再次检索 —> 思考和理性”。

看到了吧，LangGraph 这种带编排的框架指的是我把编排的权利给到模型，让模型自行去判断自己的答案合不合理，需要不需要再次进行检索判断。引用网上一张图就是：

他们的区别从名字也能看得出来，一个是链式，一个是图式，只不过这个图，是流程图的图。

由此大大缩减了Agent在回答以及工作时的幻觉问题。

## 新模式带来的延伸

有了对于工作流节点的拆分，也给Agent带来了新的能力拓展，可以在某个节点判断是否需要人工介入判断，可以引入状态机，每次节点完成记录下当前的状态（运行到哪个节点，下一步要干什么），从而在任务中断后，能从中断处进行下一次任务的持续。

这时有些聪明的小伙伴就会反问，LangChain不能做可行性判断吗？他不能记录状态吗？答案是可以的，但这一大坨循环，判断，调用就要自己写，因为LangChain它天生就不是干让模型思考的活儿的。

总的来说，这两种框架的思想更像是编程届的两种成熟思想，面向过程和面向对象。

显而易见面向过程和链式调用更像是人类的惯性思维，我先干什么，在干什么，最后干什么。

而图式和面向过程则需要编程人员有更高维的思考，我做成这一件事都需要有哪些工作，在某个工作中会不会有反向的效果，怎么做兜底处理。

由此langChain和langGraph就可以区分开了，langChain更适合搭建一个简单的问答智能体，而LangGraph才是会思考，有思想的新智能体。
