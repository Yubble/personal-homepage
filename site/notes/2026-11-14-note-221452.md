# AI 项目怎么验收优劣

前面我们讲了项目怎么做，接下来讨论下项目要怎么上线。

### 先做评估集

AI 项目有个特点，它的好不是有标准的好，不像是从数据库中查数，每次都是幂等的答案。

“这周最优惠的拼单方式是什么？”，“店里适合越野的轮胎有哪些”，这些开放性问题很难有固定的标答。传统 PRD 的要求“回答要准确”就很难推行下去。

所以我们需要先把好的标准定义出来，这套方法有个名词，叫“**评估驱动开发**”。而测试用例也变成了一个新词，**评估集**，而它和用例最大的区别是，它需要先写。因此顺序就变成了：

一、和客户一起把好的标准写下来，什么能说，什么不能说。

二、把这些标准变成一条条用例，构建评估集。

三、搭好 Harness（限制器）

四、编写 Prompt，搭 Agent

随着 Agent 的搭建，我们可能会遇到要调整评估集的情况，但是有个原则要牢记，**用例可以补充，但是修改一定慎重**，毕竟不应该是出了问题就解决提问题的人。

评估集的重要性是显而易见的，不管是换模型，还是改 Prompt，它都能告诉你功能有没有变，有没有改错，哪怕后面大刀阔斧地重构，评估集都永不过时。

### 评估集分类

* **黄金集**：核心场景标答。这里答案必须唯一，可以逐字比对。
* **异常场景集**：收录怪情况。没人写进文档的，见怪不怪的奇葩场景。比较难收集，可以让两个 Agent 同时跑，跑出的差异就是异常。
* **安全对抗集**：故意问超出安全边界的问题，测试它能不能守住安全边界。

三类评估集的上线标准是不一样的，黄金集需要接近满分，异常场景集需要逐步提升，但是不能低于上次得分（棘轮效应），安全对抗集只要出了问题，立刻停止开发，进行排查。

而 Agent 在上线之后，客户往往会问出之前从没想过的问题，这才是最有价值的，要立刻补充评估集。

### **评估集谁说了算**

尺子往往要在项目启动前做好，那究竟是谁说了算。

曹犟先生的建议是：

系统质量标准、评估集维护、回归纪律，这些属于评估面，由 FDE 负责。因为客户不需要介入具体的工程。

业务口径是否正确、结果是否有价值、最终验收是否通过，这些属于客户面，由客户负责。因为 FDE 不应该替客户拍板。

评估的目的不是通过验收，它是贯穿项目的重要部分，除了评估之外，还要回到现场看客户到底怎么用。

以上就是 FDE 施工验收的笔记总结。
